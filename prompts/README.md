# Prompts

Each pod README links here. A link opens Claude Code with the pod's repo selected and one of these files loaded as the first message. Change a file, and every pod's link changes.

## The rule behind all of them

**You think, Claude does the clerical work.** This is upskilling. Research on knowledge workers found that the more people trust an AI to do a task, the less critical thinking they do; the more confident they are in their own ability, the more they think. Tools that scaffold without fading breed dependence. So every prompt makes the builder go first, has Claude respond with questions rather than rewrites, gives more help when someone is stuck and less once they're moving, and ends by naming the skill practiced.

## Where each prompt's advice comes from

| Prompt | Practice | Source |
|---|---|---|
| `archaeology` (interviews) | Ask about specific times in the past, not hypotheticals. Talk about their life, not our ideas. Treat compliments and future promises as weak evidence. Talk less. End with "who else?" and a small ask. Capture exact quotes. | Fitzpatrick, *The Mom Test* |
| `archaeology` (case studies) | Pick cases for what they teach: extreme cases, failures, maximum variation, paradigmatic cases. Use more than one source. Keep a chain from claim to evidence. Name a rival explanation. | Yin, *Case Study Research*; Flyvbjerg, "Five Misunderstandings About Case-Study Research" |
| `players` | Map actors with their influence and connections, not just a list. Look for weak links and gaps. Revise the map after every conversation. | FSG, *Guide to Actor Mapping*; Dorst (context and field) |
| `site` | Plain language for people outside The Labs. Only claim what the research supports. Builder writes the words. | Plain-language practice; the Cycle's privacy rules |
| `prototype` | One question per prototype. Write the prediction first. Keep it rough so people are honest and nobody gets attached. Set the scene, let them use it, debrief immediately. One prototype is never enough. | Buchenau & Suri, "Experience Prototyping" (IDEO, 2000) |
| All | Scaffold, don't substitute. Learner works first, AI reviews. Fade support as competence grows. Prompt planning, monitoring and evaluation. | Collins, Brown & Newman (cognitive apprenticeship); Wood, Bruner & Ross (scaffolding); Lee et al., CHI 2025; Bjork (desirable difficulties) |

If Claude ever does the thinking for you, say so in your pod's repo and we'll fix the prompt.
